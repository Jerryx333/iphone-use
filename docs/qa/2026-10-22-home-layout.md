# 持久化主屏布局读取验收

`GET /agent/home-layout` 与 `phone_home_layout` 通过配对的 SpringBoard 服务读取
Dock、主屏页面、文件夹页面和小组件堆叠，不打开文件夹、不翻页、不移动图标。
`page` 参数筛选一个从零开始的持久化页面，保留原页索引及总页数。

2026-10-22，在 iPhone 17 Pro Max / iOS 27.2 / USB 上验证了候选 daemon 和
MCP 程序。编译及自动检查在 Mac 190 / Rust 1.98 / Xcode 27.0 完成。

- 完整布局连续读取 5 次，结果一致；耗时 102–127 ms，中位 112 ms。
- 按页 HTTP 读取与 MCP stdio 调用均成功；只读 MCP profile 包含 12 项工具。
- 候选 daemon 使用独立实例、端口、认证与运行目录，禁用 Runner 管理，Runner
  地址指向不可用端口。布局读取不依赖 XCTest 连接，结束时未取得控制租约。
- 读取前后前台应用一致。另用主屏实景逐项核对了一页：一个 4×4 小组件和其后
  两行、每行四个图标的位置吻合；验证后返回原前台应用，保留原专注模式。
- core 33 项检查及 MCP 全套检查通过（库 223 项通过、1 项忽略）；另有 3 项
  设备协议检查和 4 项 HTTP 鉴权、私有暂停、显式目标与只读方法检查通过。

设备服务返回的页面包括被专注模式或主屏设置隐藏的页面；真机中观察到了持久化
页数与可见分页数量不同。因此响应明确标识 `page_index_space=persisted_icon_state`、
`page_visibility=not_reported`，不能拿这些页码直接驱动可见分页。
行列来自序列化顺序、已知小组件跨度和设备网格尺寸；未知格式保留条目并令位置
为空、`positions_complete=false`。本接口没有像素坐标或布局恢复能力。

本轮真机验证只覆盖上述设备的 USB 路径。Wi-Fi-only、旧 iOS、iPad、自定义留空
位置及所有专注模式组合仍需分别验收。原始私人布局与截图不进入仓库。
