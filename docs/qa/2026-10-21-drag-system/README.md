# 多点拖拽的系统级验收

2026-10-21，Mac 190 / Xcode 27.0，在新建的 iPhone 17 Pro、iOS 26.2 模拟器上运行。
所有模拟器和实例均单独创建，结束后停止进程并删除模拟器。未操作个人手机。

测试 App 记录 UIKit 实际收到的触摸：按下/松手次数、取消次数、同时触点数、起终点、
经过的点、首次移动时间、边缘停留时间与总时长。每次重启使用新 nonce，先验证计数为零；
接口回执和 UI 记录必须同时通过。丢失回执不会重放手势。

| 场景 | 请求时长 | 早期密集采样版本的 UI 记录 | 修复后的 UI 记录 |
| --- | ---: | ---: | ---: |
| HTTP 单步多点拖拽 | 1900 ms | 1333 ms | 1916 ms，停留 916 ms |
| HTTP 批量多点拖拽 | 1900 ms | 1333 ms | 1916 ms，停留 916 ms |
| Flow 回放多点拖拽 | 1900 ms | 1333 ms | 1916 ms，停留 916 ms |
| 无停留的慢移反例 | 3100 ms | 416 ms | 3116 ms，仅停留 333 ms，正确判为不满足 800 ms 悬停 |
| 普通长按 | 600 ms | 599 ms | 599 ms |
| 原生 `/swipe` 兼容路径 | 700 ms | 未单独测量 | 699 ms |

每个通过的场景都只有一次按下、一次松手、一个触点，无取消；移动场景也验证了经过顺序和起终点。
时长差异发生在此 SDK/模拟器的密集移动点播放中，SDK 记录的计划总时长仍然正确。
改为每段保留一个带时刻的终点，由 XCTest 插值后，实际触摸时序符合请求。
W3C 和原生线性拖拽均使用此方式；暂停结束时仍保留原地触点。

`runner/gesture-fixture/` 是独立测试 App，不包含在控制 App 的 UI 中。
`scripts/test-drag-simulator.py` 只允许指定的模拟器目标，单步、批量和 Flow 走真实 daemon；
原生兼容路径只读取指定实例的 token，不读取默认手机 token。
原始结果、截图、来源哈希与 MCP 日志由 Simulator smoke 保存为 `simulator-gesture-evidence` artifact。

完整 Simulator smoke 的 10 项检查在 Mac 190 通过，包括位置、日志、录像、手势、MCP 实例发现和停止进程。
Settings 的预期应用名由稳定 bundle ID 和来源 PID 绑定后读取，已在中文“设置”界面验证。
验收器另有 12 项无设备测试，覆盖空回执、旧 nonce、重复触摸、错误位置、错误目标、短按冒充长按和错误应用/PID。

发送前另有 7 项服务端回归检查，覆盖旧 Runner 能力缺失、能力探测断线、浏览器短截止时间、弹窗和回执丢失。
夹具使用编译后的启动画面；若 UIKit 视口与 Runner 屏幕尺寸不同，验收器在发送前拒绝运行。

此结果证明模拟器上的 OS 触摸交付，不等同于真实 iPhone 或 SpringBoard 文件夹翻页验收。
#303 仍需在真机文件夹场景验证。
